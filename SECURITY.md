# Безпека LinguaLens

Що вже закрито, що ще відкрито, і що з цього критично перед релізом.

---

## Закрито

### Ключі AI
Живуть **лише** на сервері (`server/.env` або змінні Cloud Run). У бандл
застосунку не потрапляють — перевірено скануванням усіх 33 файлів на шаблони
`AIza…` і `sk-ant-…`. `.gitignore` закриває `server/.env`, `*.p8`, `*.p12`,
`*.mobileprovision`, `credentials.json`.

### Паролі
`crypto.scryptSync` з окремою випадковою сіллю на кожен пароль, 64 байти
виводу. Порівняння через `crypto.timingSafeEqual` — стійке до атаки за часом.
Мінімум **8 символів** (було 6: шість давало ~2 млрд варіантів, що реально
перебирається на витоку бази). Максимум 200 — щоб довгий рядок не з'їв CPU
у scrypt.

### Токени сесії
HMAC-SHA256 підпис, порівняння через `timingSafeEqual`. Живуть 180 днів.
На пристрої — у Keychain (`expo-secure-store`), не в AsyncStorage.

### Перебір пароля
Окремий лічильник: **10 спроб на 15 хвилин** з IP. До цього діяв загальний
ліміт 20/хв, який дозволяв 28 800 спроб на добу — достатньо, щоб підібрати
слабкий пароль. Мапа лічильників самоочищується, щоб не стати вектором
виснаження пам'яті.

### Розміри тіл запитів
- `/auth/*` — **4 КБ** (було 64 КБ на email+пароль)
- `/scan` — **4 МБ** (було 15 МБ; апка надсилає 150–400 КБ)

### Заголовки
`nosniff`, `X-Frame-Options: DENY`, `no-referrer`, HSTS, `no-store` на всіх
відповідях.

### Справжня IP для лімітів
Перший запис у `X-Forwarded-For` пише клієнт — підставляючи щоразу нову
адресу, можна було обійти і ліміт сканів, і захист від перебору пароля.
Тепер береться запис, доданий проксі Cloud Run (`TRUST_PROXY_HOPS`, дефолт 1).

### Помилки провайдера AI
Текст помилки Gemini/Anthropic лишається в логах сервера; клієнт отримує
загальне «AI тимчасово недоступний». Ключ Gemini передається заголовком
`x-goog-api-key`, а не в URL.

### Логи
Пошта більше не пишеться в логи. Логи Cloud Run бачить більше людей, ніж базу.

### Приватність кадру
Зображення йде в AI і **не зберігається** на сервері. Мініатюра предмета
лишається лише на пристрої користувача.

## Відкрито — критично перед релізом

### 1. Стан підписки можна підробити
`src/subscription.js` тримає статус Pro у `AsyncStorage`. Будь-хто з
jailbreak або через резервну копію може виставити `pro: true`.

**Як закрити:** після підключення StoreKit валідувати чек через App Store
Server API на нашому сервері й тримати статус у Firestore біля користувача.
Клієнт має лише кешувати відповідь сервера, не бути джерелом правди.

### 2. Токен сесії не можна відкликати
Підписаний токен дійсний 180 днів. Якщо він витік — вкрасти акаунт можна до
кінця терміну, і ми нічого не зробимо, крім зміни `AUTH_SECRET` (що вилогінить
усіх).

**Як закрити:** поле `tokenVersion` у користувача, що входить у підпис.
Зміна пароля або «вийти з усіх пристроїв» інкрементує його й миттєво
знецінює старі токени.

### 3. ~~Немає видалення акаунта~~ — закрито
`DELETE /me` видаляє запис користувача; пункт «Видалити акаунт» у налаштуваннях.

### 4. `APP_TOKEN` порожній
Публічний URL сервера без токена — це відкритий доступ до нашого Gemini-ключа
для будь-кого, хто знайде адресу. Ліміт на IP частково рятує, але не від
розподіленого зловживання.

**Як закрити:** згенерувати токен (`DEPLOY.md`, крок 2), вписати в Cloud Run
і в `src/api.js`. Це «захист від випадкових», не від цілеспрямованих — тому
основним лишається обов'язковий акаунт для сканування.

### 5. Firestore без правил доступу
Сервер ходить у Firestore через сервісний акаунт, тож клієнт напряму не
достукається. Але варто явно закрити базу правилами `allow read, write: if
false;` — щоб випадкове відкриття веб-SDK не оголило дані.

## Відкрито — варто зробити, не критично

- **Немає ротації `AUTH_SECRET`.** Зміна вилогінює всіх. Рішення: тримати
  масив секретів, підписувати першим, перевіряти будь-яким.
- **Ліміт на користувача, не лише на IP.** Зараз NAT-мережа (гуртожиток,
  офіс) ділить один ліміт. Після обов'язкової авторизації рахувати за `uid`.
- **Немає захисту від повторного надсилання.** Той самий запит можна
  відтворити. Для нашого сценарію нешкідливо, але для платних дій знадобиться.
- **`Access-Control-Allow-Origin: *`.** Для мобільного застосунку не проблема
  (Origin не надсилається), і credentials через `*` не проходять за
  специфікацією. Але коли з'явиться веб-версія — прибрати.
- **Немає моніторингу.** Різкий стрибок сканів = або вірусний ріст, або
  зловживання. Варто поставити алерт на витрати в Google Cloud Billing.

## Що перевірити перед кожним релізом

```powershell
# 1. Жодного ключа в бандлі
Select-String -Path src\*.js,App.js -Pattern "AIza|sk-ant-" 

# 2. Секрети не відстежуються git
git ls-files | Select-String "\.env$|\.p8$|\.p12$"

# 3. Ліміт бюджету в Google Cloud виставлений
# https://console.cloud.google.com/billing → Budgets & alerts
```
