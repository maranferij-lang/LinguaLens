# Скріншоти App Store

Рендер 32 кадрів для App Store: чотири локалі (uk, en-US, en-GB, es-MX) по
вісім кадрів 1320×2868 (iPhone 6.9"), напрям A «Наліпки на фіолетовому» з
брифу (`BRIEF.md`, розділи 4–7). Усе, що на кадрах схоже на застосунок, і є
застосунком: екрани знято з веб-збірки потрібної версії з демо-даними,
картки й наліпки «Поділитися», перегляд віджетів, іконка й Лінго взято з тієї
самої версії. Підписи — у `copy.js`.

## Що потрібно (Mac, один раз)

- Node 22 (як для решти проєкту) і встановлені залежності проєкту
  (`npm install` у корені).
- Playwright із Chromium. Пакет у залежності проєкту не входить, тож:

  ```sh
  npm i --no-save playwright
  npx playwright install chromium
  ```

  `--no-save` не чіпає `package.json`. Якщо Playwright уже стоїть деінде,
  можна вказати шлях: `PLAYWRIGHT=/шлях/до/node_modules/playwright/index.mjs`.
  Свій Chromium: `CHROMIUM=/шлях/до/chrome`.

ImageMagick та інші програми не потрібні: PNG без альфа-каналу пише сам
скрипт спільним кодеком проєкту (`tools/png.js`, той самий, що й для
іконок).

## Запуск

З кореня репозиторію:

```sh
node tools/store-shots/render.mjs
```

Перший запуск триває кілька хвилин: веб-збірка версії (`expo export`),
намальований арт, знімки екранів у чотирьох мовах, кадри й аркуші.

Іншу версію (гілку, тег, коміт) — через `REF`:

```sh
REF=main node tools/store-shots/render.mjs
REF=v1.3.0 node tools/store-shots/render.mjs
```

Репозиторій при цьому не змінюється: дерево версії розпаковується
(`git archive`) у тимчасову теку й після збірки зникає. Веб-збірка
перебудовується сама, коли `REF` вказує на інший коміт, ніж минулого разу.

Прапорці:

| Прапорець | Що робить |
|---|---|
| `--export` | зібрати веб-версію заново, навіть якщо коміт той самий |
| `--frames-only` | не знімати екрани наново, лише перекомпонувати кадри (секунди) |
| `--only=1,5` | лише ці кадри |
| `--locales=uk,es-MX` | лише ці локалі |
| `--no-sheets` | без аркушів для перегляду |
| `--icon=icon-eye.png` | інша іконка на кадрі 6 (тест іконки, PPO), те саме, що `ICON=…` |

Окремі кроки теж запускаються самі: `export.mjs`, `art/build-art.mjs`,
`capture.mjs [назва-знімка]`.

## Куди падає результат

Типово `store-shots-out/` у корені репозиторію (теку ігнорує git), або
`OUT=/будь-яка/тека`:

```
store-shots-out/
  uk/uk_01_scan.png … uk_08_share.png          ← це й завантажуємо
  en-US/…  en-GB/…  es-MX/…
  contact-uk.png … contact-es-MX.png           вісім кадрів локалі поруч
  search-row.png                               кадри 1–3 у розмірі пошуку (~10%)
  .work/                                       кеш: збірка, арт, знімки екранів
```

Кожен кадр рендер перевіряє: рівно 1320×2868, PNG RGB без альфа-каналу
(тип кольору 2), sRGB. Кеш (`.work`, або `WORK=…`) можна видалити будь-коли.

Статичний сервер веб-збірки бере перший вільний порт з 9100–9119 (`PORT=…`
задає свій).

## Варіант кадру 6 для тесту іконки (PPO)

Кадр 6 показує іконку застосунку на Початковому екрані. Для тесту іконки в
App Store (Product Page Optimization) варіант з іншою іконкою потребує свого
кадру 6. Іконку бере `ICON=…` або `--icon=…`: ім'я файла з `assets/` знятої
версії (експорт кладе в кеш усі `assets/icon-*.png`) або шлях до PNG. Після
основного рендера, з тим самим кешем:

```sh
OUT=store-shots-out/ppo-icon-eye WORK=store-shots-out/.work REF=… \
  node tools/store-shots/render.mjs --frames-only --only=6 --icon=icon-eye.png
```

Вийде `ppo-icon-eye/<locale>/<locale>_06_widget.png` для кожної локалі й
аркуш `contact-icon.png` (кадр 6 усіх локалей поруч). Решту кадрів варіант
бере з основного набору. Якої іконки немає, рендер не підмінює основною, а
зупиняється з помилкою.

## Локалі

| Локаль | Інтерфейс | Слова на наліпках | Переклади |
|---|---|---|---|
| uk | українська | англійська США 🇺🇸 (mug /mʌɡ/, sneaker) | українські |
| en-US | англійська | іспанська Латинської Америки 🇲🇽, з артиклем (la taza /la ˈtasa/) | американські |
| en-GB | англійська | англійська Британії 🇬🇧 (trainer, rucksack, /ˈhaʊsplɑːnt/) | українські: так застосунок бачить українець з англійським телефоном |
| es-MX | іспанська | англійська США 🇺🇸 | іспанські (мексиканські: audífonos, lentes) |

Варіант мови на наліпках той, який застосунок дав би людині на цій сторінці
(`src/langVariants.js`): від нього прапорець, голос і те, як сервер пише
слово (`VARIETIES` у `server/ai.js`: правопис, словник, IPA).

- **uk і es-MX:** англійська США, як за замовчуванням усюди: General
  American (sneaker, /ˈhaʊsplænt/, /ˈwɪndoʊ/), голос en-US.
- **en-US:** іспанська Латинської Америки, за замовчуванням в обох
  Америках: голос es-MX, сесео (z і c перед e/i — /s/: /la ˈtasa/,
  /la manˈsana/), мексиканські й нейтральні слова (los audífonos, los
  tenis, los lentes, la tabla de picar, la cobija; жовтий лимон — el
  limón amarillo, бо «el limón» у Мексиці — лайм). Слово віджета — la
  resiliencia (/la resiˈljensja/), як resilient на інших сторінках.
  Іспанської Іспанії (θ, auriculares, gafas) тут немає.
- **en-GB:** англійська Британії: RP (/ˈhaʊsplɑːnt/, /ˈwɪndəʊ/,
  /əˈlɑːm klɒk/, без «r» після голосної) і британські слова (trainer,
  rucksack, chopping board, tea towel), голос en-GB. За замовчуванням і в
  Британії вчать американську, тож людина обирає британську сама; засів
  кладе цей вибір у налаштування (`variantsFor` у `data.mjs`), як зробив
  би список мов.

IPA іспанських слів з артиклем і вузька, як у сервера (/el ˈliβɾo/): b, d,
g після голосної, і через межу слова, — β, ð, ɣ (/la βenˈtana/). Засів кладе варіант і в кеш
слова дня, з тими самими варіантами, з якими застосунок його звіряє. Окремі
елементи (картки й наліпки кадру 8, віджети) отримують варіанти так само:
`shot-gallery.js` бере `setChosenVariants` застосунку через прокладку
`shot-variants.js`, яку пише `export.mjs` (у версії без варіантів мов це
заглушка). На кадрі 5 рендер ще й шукає прапорець варіанта на чипі мови:
не той прапорець дасть у журналі «pf-level.flag: not found». Усе це
стереже тест `__tests__/storeShotsData.test.js`: якщо варіанти застосунку
зміняться, тест нагадає змінити й дані.

Рушник для посуду в іспанській — «el trapo de cocina» (просто «trapo» —
ганчірка).

Перший день тижня на смужці серії (кадр 7) — як у календаря iPhone регіону
локалі (`firstWeekdayFor` у `data.mjs`, за CLDR): en-US і es-MX з неділі,
uk і en-GB з понеділка. Веб-збірка цього не знає й завжди бере понеділок,
тож `capture.mjs` підставляє сторінці число, яке віддав би iPhone.

Демо-слова, приклади й слова дня лежать у `data.mjs`. Словник і профіль
засіяні однаково: 30 слів (16 наліпок колекції й 14 старіших без фото), тож
«Збережено: 30» на кадрі 2 і «30 слів усього» в профілі не сперечаються.

Дати, які малює сам рендер (екран блокування кадру 6) і картки «Поділитися»
кадру 8 (діапазон тижня, дата внизу), у форматі локалі магазину: en-GB
«Tuesday 6 October», «30 Sept–6 Oct». Дата екрана блокування така, як її
пише iOS цією мовою, тобто uk і es з малої: «вівторок, 6 жовтня», «martes,
6 de octubre» (`lockScreenDate` у `layout.js`). Застосунок сам форматує
англійські дати як en-US; рендер передає картці локаль явно. Дати
всередині знятих екранів такі, як їх показує застосунок. Діапазон тижня
на картці склеєно коротким тире без пробілів: правило власника дозволяє
його в діапазонах у застосунку (`__tests__/noLongDashes.test.js`).

Транскрипцію застосунок пише системним заокругленим шрифтом (SF Pro
Rounded на iPhone, `F.ipa` у `src/theme.js`). SF поза Apple немає, тож на
знімках його заміняє Inter (`IPA_FONTS` у `paths.mjs`, лежить у
залежностях проєкту): повний IPA, близькі метрики. Тексти з
`adjustsFontSizeToFit` у перегляді віджетів iPhone зменшує, щоб умістились
у рядок, а веб обрізав би їх трьома крапками; `capture.mjs` зменшує їх так
само, до того ж `minimumFontScale`.

## Підписи

`copy.js` — звичайний ESM-модуль, його читають і рендер, і jest
(`__tests__/storeShotsCopy.test.js`). Тест стереже:

- 4 локалі × 8 кадрів в одному порядку;
- заголовок ≤ 28 символів (примусовий перенос `\n` дозволено), підрядок ≤ 46;
- **жодного тире** (правило власника): ні «—», ні « – » чи « - » як тире, ні
  навіть короткого в діапазоні; рівні словами: «від A1 до C2», «A1 to C2»,
  «de A1 a C2»;
- без цін, «free», «безкоштовно», «gratis», «№1» і чужих брендів;
- підстановки лише `{LANGS}` і `{ACH}`; числа беруться з тієї ж версії, що й
  екрани, а для uk ще й перевіряється узгодження («29 досягнень»);
- кадр 1 називає мову, якої вчать (пошук бачить лише кадри 1–3);
- плашка PRO — лише на кадрі 4 (сцена — функція Pro, правило 2.3.2).

`[слова]` у заголовку — ключові слова, `\n` — перенос там, де автоматичний
розбив би фразу невдало. Заголовок має бути у два рядки, як на сусідніх кадрах: рендер попереджає про інший (однорядковий він ще й опускає на пів рядка), а `\n` це виправляє.

## Справжні фото замість намальованих

Кадри 1, 2 і 4 зараз на намальованих «фото» (`art/`): чашка на столі,
колекція предметів, кухня. Бриф (§9) хоче справжні. Склади фото в будь-яку
теку й передай її в `PHOTOS`:

| Файл | Кадр | Що на фото |
|---|---|---|
| `hero.jpg` | 1 | червона чашка на столі, портрет 9:16 (1080×1920). Чашка — у верхній середині кадру, там, де рамка прицілу сканера: приблизно 25–75 % ширини й 27–55 % висоти. Наліпку кадру 1 застосунок ріже з цього фото по контуру, тож обирай кадр, де крізь ручку не видно стіни (ручка вбік від камери або однотонне світле тло) і стільниця біля дна однотонна й світла: інакше вони потраплять у вирізку |
| `kitchen.jpg` | 4 | кухня, портрет 9:16 (1080×1920), з предметами window, plant, pan, jar, board, kettle, apple, mug, towel (яких немає — просто не буде підписів). На картці сцени кадру 8 дошка й рушник вимкнені («Показувати на картці»): там їхні фішки різала б картка тижня |
| `obj-<key>.jpg` | 2 (і 3, 8) | квадратне фото одного предмета по центру (800×800). `key`: mug, plant, apple, headphones, sneaker, lemon, camera, backpack, umbrella, clock, book, cactus, glasses, kettle, banana, scissors |

Потрібні не всі: чого немає, лишається намальоване. Наліпку кадру 1 рендер
ріже з самого `hero.jpg` по контуру предмета, рівно як застосунок
(`cutout.js`): що всередині контуру (стіл біля дна, стіна в ручці), те й на
наліпці. Тому для фото потрібні й контури. Їх дає той самий AI, що й
у застосунку (ключ із `server/.env`, як для локального сервера в
`SETUP_MAC.md`, розділ 3):

```sh
PHOTOS=~/Desktop/store-photos node tools/store-shots/scan-photos.mjs
PHOTOS=~/Desktop/store-photos node tools/store-shots/render.mjs
```

Намальований замінник робить те, що на справжньому фото робить вибір кадру
з однотонним світлим тлом: тло «фото» в межах вирубки кожної наліпки біле,
як облямівка (`art/backing.js`), тож у ручці чашки не видно стіни, між
носиком і чайником плитки, а під дном стола. Вирубка та сама, якою ріже
застосунок: `stickerPath` для наліпок колекції, контур сцени з запасом
`SceneArt`, квадрат кропу сканера для кадру 1 (це стереже
`__tests__/storeShotsBacking.test.js`). Кадр сканера на кадрі 1 показує
`hero.jpg` як є, а наліпку ріже з копії `hero-sticker.jpg`; на фото кухні
біле лежить лише під піднятими предметами, і його закриває біла облямівка
їхніх наліпок (дошку й рушник картка сцени кадру 8 не піднімає, тож їм
підкладки немає). Справжні фото з `PHOTOS` нічого такого не отримують.

`scan-photos.mjs` пише `shapes.json` у ту саму теку й показує, як модель
назвала кожну річ. Слова на кадрах беруться з `data.mjs`: якщо твоя річ
інша, виправ слово там. Без контуру рендер попередить: наліпку вирізало б
по намальованому предмету.
