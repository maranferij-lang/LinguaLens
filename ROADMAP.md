# LinguaLens — розбір і план до App Store

Стан на жовтень 2026. Що тут є, що зламано, що виправлено і в якому порядку
доводити до релізу.

---

## 1. Архітектура одним поглядом

```
iPhone (Expo SDK 54, React Native 0.81, JavaScript)
│
├── App.js — єдиний «мозок»: увесь стан (слова, налаштування, підписка,
│            статистика, досягнення), 5 вкладок без навігаційної бібліотеки
├── src/*Screen.js — екрани, отримують дані й колбеки через пропси
├── AsyncStorage — УСІ дані користувача: слова, SRS, статистика, Pro-статус
├── SecureStore  — токен сесії
└── Documents/stickers — фото-наліпки збережених слів
        │
        │  HTTPS (Bearer-токен або спільний APP_TOKEN)
        ▼
server/ (Node 20, без залежностей, Cloud Run)
├── /scan         — кадр → Gemini або Claude → слово, IPA, переклад, приклад, рамка, силует
├── /auth/*, /me  — email+пароль (scrypt), HMAC-токени, видалення акаунта
├── /word-of-day  — 320 слів, свій порядок для кожного юзера, переклад з кешем
└── Firestore (REST) або data.json локально
```

### Що зроблено добре

- **Ключі AI лише на сервері.** Апка не знає жодного ключа — правильно.
- **Дизайн-система.** `theme.js` і `motion.js` — продумані токени, криві,
  пружини, «менше руху». Рідко буває в pet-проєкті на такому рівні.
- **Сервер без залежностей.** Нема що оновлювати, нема supply-chain ризиків,
  холодний старт на Cloud Run — миттєвий.
- **Ліміти перевіряються до зйомки**, пейвол підлаштовується під причину,
  кадр не зберігається на сервері.

### Слабкі місця архітектури

| Проблема | Чому це важливо |
|---|---|
| `App.js` (~680 рядків) тримає весь стан, у `SettingsScreen` летить 20+ пропсів | Кожна нова фіча (покупки, синхронізація) роздуватиме його далі. Немає навігації — немає жесту «назад», не можна відкрити екран із пушу. |
| **Акаунт майже нічого не дає.** Слова, статистика, Pro — лише на телефоні; сервер знає тільки email, ім'я й аватар | Акаунт тягне за собою вимоги Apple (видалення, політика приватності), а користі для людини — нуль: новий телефон = порожній словник. |
| Ліміти й Pro-статус живуть в AsyncStorage | Перевстановив застосунок — знову 5 сканів. Гість зі спільним `APP_TOKEN` має необмежений доступ до вашого AI-ключа (лише 20/хв на IP). |
| Немає TypeScript і жодного тесту | Помилку, яка валила весь сервер (див. нижче), ловить перший же запуск будь-якого тесту. |

## 2. Що виправлено в цій гілці

| # | Баг | Наслідок | Виправлення |
|---|---|---|---|
| 1 | **`SECURITY_HEADERS` не оголошений** у `server.js` | Сервер **падав на першому ж запиті**, навіть `/health`. Жоден скан не міг пройти | Константа оголошена; кожен обробник загорнутий у `catch` → помилка дає 500, а не вбиває процес |
| 2 | Нативні модулі SDK 57 (`expo-asset@57`, `expo-constants@57`) у lock-файлі поряд із SDK 54 | `expo-doctor`: «duplicate native modules» — нативна збірка EAS ламається або падає на старті | Встановлені версії під SDK 54 як прямі залежності; дублікатів немає |
| 3 | Силует наліпки рахувався без урахування пропорцій кадру (3:4) і зсуву квадрата біля країв | Вирізка «їхала» від предмета на 7–10% розміру наліпки, біля краю кадру — більше. А це і є головна «вірусна» фішка | Сканер перераховує силует у координати вирізаного квадрата в момент кропу (`shape`); старі слова малюються як раніше |
| 4 | Фото наліпок зберігались абсолютним шляхом у кеші | iOS чистить кеш, а шлях до контейнера змінюється **після кожного оновлення з App Store** → усі наліпки в словнику зникали б | Фото копіюється в `Documents/stickers`, у слові — відносний шлях (`src/photos.js`); видалення слова прибирає файл |
| 5 | Гість міг відредагувати ім'я в профілі | Застосунок створював «фальшивого» залогіненого юзера без email і токена | Тап по профілю гостя веде на вхід |
| 6 | Лічильник сканів не скидався, якщо апку не закривали з учора | Зранку — пейвол «скани закінчились» без жодного скану | Ліміт рахує лише сьогоднішні скани |
| 7 | Ліміт «1 мова безкоштовно» рекламувався в пейволі, але не діяв (`canUseLanguage` ніде не викликався) | Обіцянка в пейволі не відповідала поведінці | Підключено до вибору мови; на мову, де вже є слова, перемикатись можна завжди |
| 8 | Немає видалення акаунта | Відмова Apple за Guideline 5.1.1(v) | `DELETE /me` + пункт у Налаштуваннях |
| 9 | Ліміти брали **перший** запис `X-Forwarded-For`, який пише сам клієнт | Підміною заголовка обходився і ліміт сканів, і захист від перебору пароля | Береться запис, доданий проксі Cloud Run (`TRUST_PROXY_HOPS`) |
| 10 | Відповідь «предмет не видно» (422) показувалась як «сервер не зміг» | Людина думала, що зламався сервер, а не що треба підійти ближче | 422 → «підійди ближче», 504 → «надто довго» |
| 11 | Після відмови в доступі до камери кнопка «Дозволити» нічого не робила | Глухий кут — iOS вдруге не питає | Кнопка веде в Параметри з поясненням |
| 12 | Слово дня перекладалося на 7 днів **послідовно** | 10+ с очікування на холодному кеші | Паралельно |
| 13 | Текст помилки Gemini/Claude віддавався клієнту; ключ Gemini — у URL | Витік деталей інфраструктури; ключ у логах проксі | Деталі лише в лог; ключ у заголовку `x-goog-api-key` |
| 14 | Подвійний тап у квізі зараховував відповідь двічі | Неправильний рахунок і «ідеальний квіз» | Захист через ref |

Перевірено: сервер пройшов наскрізний прогін (`/health`, реєстрація, `/me`,
видалення, ліміт входу з підробленим заголовком), застосунок збирається
(`expo export --platform ios`), логіка лімітів перевірена тестовими
сценаріями. **На реальному iPhone ці зміни ще не запускались** — див. етап 1.

## 3. Блокери релізу — без них App Store не прийме

### 3.1. Оновити Expo SDK 54 → 57
Expo Go з App Store відкриває лише останній SDK (зараз 57), тож тестувати
проєкт у ньому вже не вийде. До того ж `AGENTS.md` посилається на документацію
SDK 57, а код — на 54.

```powershell
npx expo install expo@^57
npx expo install --fix
npx expo-doctor
```

Окремим кроком, із тестом на пристрої. Що перевірити після оновлення:
`expo-camera`, `expo-notifications`, `expo-audio`; `ImageManipulator.manipulateAsync`
застарів — перейти на `ImageManipulator.manipulate(uri)…renderAsync()`.
Для подальшої роботи (і обов'язково для покупок) — **development build**
замість Expo Go: `npx expo install expo-dev-client`, `eas build --profile development`.

### 3.2. Справжні покупки
Зараз «Спробувати безкоштовно / Отримати Pro» **вмикає Pro безкоштовно**.
Рецензія відхилить (Guideline 3.1.1), а якщо пройде — Pro отримає кожен.

Найкоротший шлях — **RevenueCat** (`react-native-purchases`): він сам
перевіряє чеки, рахує тріали, дає вебхуки на сервер і готовий «Restore».
Альтернатива — `expo-iap` + власна перевірка через App Store Server API.

- [ ] 4 продукти в App Store Connect з ID із `PLANS[].productId`
- [ ] `purchasePlan()` → справжня покупка; ціни брати з магазину, а не з `PLANS[].price`
      (у кожній країні своя ціна й валюта)
- [ ] «Відновити покупки» працює
- [ ] Посилання **Terms of Use (EULA)** і **Privacy Policy** у пейволі — обов'язкові (3.1.2)
- [ ] Для активної підписки — посилання на керування в налаштуваннях Apple ID

### 3.3. Ліміти — на сервері, а не в телефоні
Після покупок сервер має знати, хто Pro (вебхук RevenueCat / App Store Server
Notifications → поле в Firestore). Тоді `/scan` сам рахує 5 сканів на день за
`uid` (або за анонімним ID пристрою для гостя) і відповідає 402, коли ліміт
вичерпано. Інакше один ентузіаст зі скриптом спалить ваш бюджет на AI.

### 3.4. Сервер у хмарі + адреса в апці
`PRODUCTION_URL` у `src/api.js` — досі плейсхолдер `…xxxxx…`. У релізній
збірці мережа не працюватиме взагалі. Порада: брати адресу з
`process.env.EXPO_PUBLIC_SERVER_URL` (змінні оточення EAS), щоб не правити код
перед кожною збіркою. Не забути: бюджетний алерт у Google Cloud Billing.

### 3.5. Юридичне й метадані
- [ ] Політика приватності — **чесна**. Чернетка в `APPSTORE.md` каже, що дані
      потрібні «щоб синхронізувати прогрес», але слова на сервер не потрапляють.
- [ ] `NSCameraUsageDescription` — англійською за замовчуванням, українська через
      `"locales"` у `app.json`. Рецензент читає англійською.
- [ ] Після першої збірки перевірити Privacy Manifest (`PrivacyInfo.xcprivacy`)
      — Apple відхиляє збірки без оголошених «required reason API».
- [ ] Перевірка в авіарежимі: кожен екран має пояснювати, що сталося.
- [ ] Скріншоти 6.9", опис, ключові слова (див. `APPSTORE.md`).

## 4. Продуктові рішення, які варто ухвалити до релізу

### Акаунти: прибрати або зробити корисними
Зараз акаунт дає ім'я, аватар і «слово дня» — і більше нічого. При цьому:
- **Слово дня для гостя не працює.** Онбординг просить дозвіл на пуші й
  обіцяє «нове слово щодня», але сервер віддає слова лише залогіненим — гість
  не отримає жодного пушу.
- Новий телефон = порожній словник, навіть з акаунтом.

**Рекомендація для v1:** гість за замовчуванням. Слово дня — за анонімним
seed пристрою (сервер уже вміє перемішувати під seed). Pro прив'язаний до
Apple ID через RevenueCat, «Відновити покупки» переносить його на новий телефон.
Менше екранів, менше вимог Apple, швидший реліз.

**Для v1.1:** хмарна синхронізація словника + **Sign in with Apple** — тоді
акаунт стає цінністю (бекап, кілька пристроїв), а не формальністю.

### Вірусність — зараз її механізму немає
«Вірусна фішка» — наліпки-вирізки предметів — красиві, але ними **неможливо
поділитись**. Без цього немає й росту.
- Кнопка «Поділитись» на картці результату: наліпка + слово + IPA у
  фірмовій рамці → картинка (`react-native-view-shot`) → `Share` / Instagram Stories.
  На картці — назва застосунку. Це головний канал безкоштовного трафіку.
- «Колекція» наліпок як сітка — візуальний трофей, яким хочеться хвалитись.
- Кілька предметів з одного кадру (ідея вже є в `MONETIZATION.md`) — сильний Pro-аргумент.

### Навчання
- У флешкартках і квізі **немає кнопки виходу** посеред сесії — лише перемкнути вкладку.
- Відповіді квізу не впливають на SRS, а «повторити все», коли нічого не
  настав час повторювати, підвищує інтервали — зубріння ламає розклад.
- Для німецької слово приводиться до нижнього регістру й без артикля
  (`tasse` замість `die Tasse`) — для вивчення мови це помилка.

## 5. Технічний борг (після релізу, але не відкладати надовго)

- **Стан і навігація.** Винести стан з `App.js` у стор (Zustand або
  Context + reducer), вкладки — на `expo-router`. Тоді пуш «слово дня»
  зможе відкривати картку слова (зараз тап по пушу просто відкриває апку).
- **TypeScript і тести.** Почати з чистої логіки: `srs.js`, `subscription.js`,
  `achievements.js`; для сервера — `node:test` на кожен ендпоінт.
- **Моніторинг крашів** — Sentry. `ErrorBoundary` зараз пише лише в консоль.
- **Продуктивність сканера.** `takePictureAsync` знімає повні 12 Мп, а потім
  стискає до 1024 px — це зайві сотні мілісекунд на кожному скані. Задати
  менший `pictureSize`. PNG маскота по ~230 КБ кожен — зменшити до потрібного
  розміру.
- **Сховище слів** — один JSON у AsyncStorage, перезаписується цілком при
  кожній зміні. До ~1000 слів це нормально; для синхронізації — `expo-sqlite`.
- **Слово дня й часові пояси.** Сервер рахує дати в UTC — у США ввечері
  картка «слово дня» може бути порожньою. Передавати локальну дату з клієнта.
- **Безпека:** відкликання токенів (`tokenVersion`), одночасна реєстрація
  з однаковим email створює дубль (у Firestore — документ на email з `exists=false`).
- **Локалізація:** у `de`/`es` бракує 57 рядків — інтерфейс змішаний з англійською.

## 6. Порядок дій

1. **Перевірити цю гілку на iPhone** (development build): скан → наліпка
   лежить рівно по предмету → зберегти → перезапустити → наліпка на місці;
   видалити акаунт; відмовити камері й увімкнути через Параметри.
2. **SDK 57 + dev build + TestFlight** для себе.
3. **Сервер у Cloud Run** + `EXPO_PUBLIC_SERVER_URL` + бюджетний алерт.
4. **Рішення щодо акаунтів** (розділ 4) — від нього залежить наступний крок.
5. **RevenueCat + серверні ліміти** + Terms/Privacy.
6. **«Поділитись наліпкою»** — до релізу, бо перші користувачі — найцінніший трафік.
7. Метадані, скріншоти, локалізація дозволів → **подача на рецензію**.
