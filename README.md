# LinguaLens 📷 → 🌍

Застосунок для iPhone: наводиш камеру на предмет і отримуєш його назву мовою,
яку вчиш, з транскрипцією, перекладом, прикладом і озвучкою. Предмет
вирізається по контуру й стає наліпкою у твоїй колекції. Слова потрапляють у
флешкартки з інтервальним повторенням і в квіз, а найкращим можна поділитися
картинкою в Stories.

Реєстрації немає: відкрив застосунок і одразу скануєш. Ключі AI живуть тільки
на сервері, тож користувачу нічого не треба налаштовувати.

## Як це влаштовано

```
iPhone (Expo SDK 57 · React Native 0.86 · React 19.2)
│  слова, прогрес, налаштування   → AsyncStorage
│  фото наліпок                   → Documents/stickers
│  анонімний токен пристрою       → Keychain (переживає перевстановлення)
│
├─ HTTPS ─► сервер (Node, без npm-залежностей, Google Cloud Run)
│            POST /auth/device          новий пристрій → випадковий id + токен
│            POST /scan                 кадр → AI → слово, рамка, силует
│                                       (5 безкоштовних сканів на день, далі 402)
│            GET  /word-of-day          7 днів слів під seed пристрою
│            GET  /me · DELETE /me      Pro-статус і лічильник · стерти дані
│            GET  /privacy · /health    політика приватності · перевірка
│            POST /webhooks/revenuecat  зміни підписки
│              │
│              ├─► Gemini або Claude    ключі лише тут
│              └─► Firestore            (локально — server/data.json)
│
└─ StoreKit ─► RevenueCat ─(вебхук + REST-перевірка)─► сервер
```

- **Акаунтів немає.** При першому запуску застосунок тихо отримує від сервера
  випадковий id. Сервер не знає ні імені, ні пошти. Слова й прогрес ніколи не
  залишають телефон.
- **Ліміт сканів рахує сервер** за id пристрою, а не телефон. Перевстановлення
  його не обнуляє, і запит понад ліміт відхиляється ще до виклику AI.
- **Pro прив'язаний до того ж id.** RevenueCat повідомляє сервер вебхуком, а
  на випадок, якщо вебхук загубився, сервер сам перепитує (кеш 10 хв).
  Покупка переноситься на новий телефон через «Відновити покупки».

## Швидкий старт на Mac

Новий Mac, на якому ще нічого немає: спершу [`SETUP_MAC.md`](SETUP_MAC.md)
(Xcode, Homebrew, Node 22, CocoaPods). Далі:

```bash
cd ~/Documents/LinguaLens
npm install

# вікно 1 — сервер без жодних ключів (завжди відповідає «кружка»)
cd server
cp .env.example .env
npm run dev
```

```bash
# вікно 2 (⌘T) — застосунок
cd ~/Documents/LinguaLens
npm run start:go     # i → Expo Go у симуляторі, або QR → Expo Go на iPhone
```

Адресу локального сервера вписувати не треба, застосунок знаходить її сам.
Камера є тільки на справжньому iPhone. Щоб розпізнавати справжні предмети,
впиши в `server/.env` `PROVIDER=gemini` і `GEMINI_API_KEY=…`
([безкоштовний ключ](https://aistudio.google.com/apikey)) і запусти `npm start`.

Для справжніх покупок, сповіщень і сплешу потрібна development build:
`npx expo run:ios` (симулятор) або `npx expo run:ios --device` (iPhone на кабелі).
Після неї `npx expo start` → `i` відкриває вже її, а не Expo Go.

Налаштування застосунку задаються змінними `EXPO_PUBLIC_*`: локально в `.env`
(зразок у [`.env.example`](.env.example)), для збірок через `eas env:set`
(див. [`USER_TODO.md`](USER_TODO.md), крок 7).

## Дизайн-система

Макети: [Figma](https://www.figma.com/design/c5DX8UXHJUdO58fwjIRTFq) — 11 екранів
у світлій темі, 3 у темній, токени й компоненти на сторінці Foundations.
Код і макет тримають ті самі значення; звірка — у `figma/STATE.md`.

**Тепла крейда + один акцент.** Тло ніколи не чисто-біле (`#FAF8F4`). Акцент
`#5B4FD6` узятий піпеткою зі шкіри маскота Lingo і поглиблений до контрасту
5.6:1 на цьому тлі. Це єдиний насичений колір інтерфейсу: бірюза з його
черевця працює тільки на станах успіху, бурштин — тільки на серії днів,
червоний — тільки на помилці. Тіні теплі (`#5C4F3D`), не сірі: сіра тінь на
теплому тлі виглядає брудно.

Тема одна, фірмова, у світлому й темному варіанті, плюс «Авто». Старі ключі
тем із попередніх версій мігрують автоматично (`resolveThemeKey`).

Рух і типографіка зібрані за двома опублікованими наборами правил:
[emilkowalski/skills](https://github.com/emilkowalski/skills) (design engineering, `apple-design`)
і [Nutlope/hallmark](https://github.com/Nutlope/hallmark).

`src/motion.js` — єдине джерело правди для анімацій:

| | |
|---|---|
| **Криві** | посилені безьє: `out (0.23,1,0.32,1)`, `inOut`, `drawer` з iOS. `ease-in` на UI не використовується ніде: він гальмує саме тоді, коли око найуважніше |
| **Тривалості** | натиск 120 · підказка 190 · панель 240 · аркуш 280 · **вихід 170**. Вихід завжди швидший за вхід |
| **Пружини** | задаються як в Apple, парою `(response, damping)`, а не масою й жорсткістю. За замовчуванням `damping 1.0`, тобто **без перельоту**: елемент, який просто з'явився, ніхто не кидав. Переліт (`0.82`) лишився у двох місцях: «поп» щойно вирізаної наліпки і повернення аркуша слова, якщо його не дотягнули |
| **Стагер** | 55 мс між сусідніми елементами, обрізка на шостому |
| **Продуктивність** | анімації йдуть через `useNativeDriver`, на GPU. Прогрес-бари масштабуються по X замість зміни `width` |
| **Reduced motion** | системне «Зменшення руху» прибирає зсуви, масштаб і переліт, але лишає непрозорість і хаптику |

`src/theme.js`: трекінг і інтерліньяж залежать від кегля (правило Apple: одне
значення на всі розміри завжди десь хибне): 34 pt → −0.75, 17 pt → −0.10,
дрібні кепси → +1.1. Функція `type(size, family)` повертає готовий стиль.

`src/Chrome.js`: таб-бар як напівпрозорий матеріал з `expo-blur`. Контент
проїжджає під ним, а замість жорсткого роздільника там світлий край.

## Як працює «слово дня»

1. Кожен пристрій при першому запуску отримує на сервері випадковий `seed`.
2. Сервер детерміновано перемішує 320 слів під цей seed, тож у кожного свій порядок.
3. Слово на день N = `порядок[(індекс_дня + N) % 320]`, тому повторів немає приблизно 11 місяців.
4. День рахується за **локальною датою телефону**, а не за UTC сервера: інакше
   ввечері в США картка була б порожня.
5. Застосунок тягне 7 днів наперед, кешує їх і планує 7 локальних сповіщень на
   вибрану годину. Переплановуються лише ці сповіщення, нагадування про
   пробний період лишається.
6. Переклади кешуються на сервері, тож та сама пара мов не запитується в AI двічі.
